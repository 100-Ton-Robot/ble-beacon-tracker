# Changelog

Scanner firmware versions come from `scanner_fw/VERSION`; the gateway and the shield deck have no
version numbers yet. All versions below were made between 2026-10-29 and 2026-10-31; dates are
when the image was built, where known.

## Unreleased

### Gateway

Needs scanner firmware **0.4.0 or later** (protocol 3): v2 and v1 frames are dropped as bad.

- Removed (2026-11-11): the sector claim check, left over from before scanner 0.5.0 (which
  stopped sending the claim, so an absent claim read as 0 and the sectors on pins 1 and 2 were
  flagged `suspect` with a `SECTOR_MISMATCH` every minute). The RX pin is the sector. Gone:
  `SECTOR_MISMATCH`, `SECTOR_NOT_CONFIGURED`, `claim` in the `rssi` and `status` JSON, the
  retained `<sector>/claim` topic (its old value is cleared at connect) and the `sector`
  command. A claim still sent by an older scanner is ignored.
- Changed (2026-11-11): `SECTOR_OK` is now `CHIP_OK` (the expected chip is back), and the
  binary sensors are "Sector N chip mismatch" (new Home Assistant entity IDs). Only
  `expected_chip` sets them.
- Fixed (2026-11-11): input from the scanners is checked before it is published. A bucket whose
  chip ID isn't 8 bytes is dropped (a bad frame; a shorter one used to be zero-padded); single
  records with an address that isn't 6 bytes, advert data over 31 bytes, a known kind that isn't
  a sub-message or an unknown kind above 63 are dropped and counted in the new `bad_records`
  (status JSON; logged at most once a minute). Unknown kinds 9-63 still go to `raw/<n>`.
  Scanner `version` and event `text` are cleaned like advert names (control characters as
  `?`, non-ASCII as `?` unless valid UTF-8).
- Fixed (2026-11-11): MQTT commands with control or non-ASCII characters or over 128
  characters are dropped, and warnings no longer repeat the rejected text (log injection).
- Fixed (2026-11-11): `tools/make_selftest.py` runs again; the self-test data is regenerated
  from it and covers the retired claim field, `ignore list`, `debug`, `TxDrops`, a short chip
  ID, malformed records and unclean text.
- Changed (2026-11-02): reads protocol 3 (protobuf `Bucket` every 200 ms, CRC + COBS) with a
  small hand-written wire-format reader (`pb_wire.h`); unknown fields are skipped and unknown
  record kinds published as hex on `<sector>/raw/<n>`. UART RX buffers 4096 bytes.
- Changed (2026-11-02): MQTT layout v3 replaces the one JSON message per sector per second:
  `<sector>/rssi` (one batched message per bucket), `<sector>/adv/<ADDR>` (Theengs-style
  advert / scan response fields), `<sector>/status`, `<sector>/counters`, mast-wide `events`
  and `security`, and retained, change-only scanner state (`online`, `chip`, `claim`, `load`,
  `flash`, `listening`, `client`, `test_image`, `active`, `payloads`, `ant`). Nothing per
  address is retained. `t` is epoch milliseconds. Topics and payloads: `gateway/README.md`.
- Added (2026-11-02): `bletracker/<mast>/online` (MQTT birth / last will), retained
  `bletracker/<mast>/info` (`"format":3`), and gateway commands on `bletracker/<mast>/cmd`:
  `reboot`, `clear`. The gateway deletes and republishes its retained topics at every MQTT
  connect.
- Added (2026-11-02): SNTP clock (`ntp_server` substitution, default `pool.ntp.org`).
- Changed (2026-11-02): the gateway no longer sets the scanner's sector. It checks each
  bucket's sector claim against its RX pin (and an optional expected chip ID): mismatches are
  SECURITY errors, mark that sector's data `suspect` and turn on a "Sector N mismatch" binary
  sensor.
- Added (2026-11-02): protobuf commands with a gateway seq and ack tracking (`CMD_OK` /
  `CMD_REJECTED`, warning after 2 s without one); `payloads`, `active`, `budget`, `intervals`
  and a manual addressed `sector` command; JSON `{"cmd": ...}` accepted.
- Added (2026-11-02): settings the scanners forget at boot (payloads, active scanning,
  intervals, budget) are YAML options the gateway keeps applied.
- Added (2026-11-02): gateway-side throttle that lowers the scanners' budget when the gateway
  can't keep up; "Gateway load" and per-sector load / lost buckets / bad frames / devices /
  mismatch / chip sensors.
- Added (2026-11-02): boot self-test against the contract's command vectors and sample buckets
  generated by `gateway/tools/make_selftest.py`; result in a "Self test" text sensor.
- Changed (2026-11-02): YAML is one `sector_scanner:` hub with a `sectors:` list.

Earlier, frame v2 (scanner firmware 0.3.0):

- Changed: reads frame v2 only (16-byte header with `chip_id`).
- Added: learns each RX pin's chip ID (`chip` in the JSON, a chip text sensor per sector) and
  sets the scanner's sector to its pin's (command 4, addressed, at most every 5 s).
- Added: one shared command TX (GPIO21) to every scanner's D7. Addressed v2 commands come from
  MQTT `bletracker/<mast>/<sector>/cmd` and `bletracker/<mast>/all/cmd` (`listen`, `flash`,
  `ant`, `reboot`). Each sector gets Home Assistant buttons for flash mode and reboot.
- Added: JSON fields `scanner_sector`, `listening`, `flash`, `client`, `test_image`.
- Changed: pins are RX GPIO17/16/18 (header 34/32/31) and TX GPIO21 (35). GPIO1 and GPIO2 are
  free now.
- Changed: Home Assistant entities come over the ESPHome API and MQTT discovery is off. MQTT
  carries only beacon data and commands.
- Changed: the `api_key` secret (used for both API and OTA) replaces `ota_key`. The `mast`
  substitution names the device.
- Changed: the config is split into `packages/bletracker-gateway.yaml` (shared by every mast)
  and a per-mast file (`example-mast.yaml`). `bletracker-gateway.yaml` is no longer a device
  config on its own.

### Docs

- Added `security_acceptance.md` (2026-11-11): the gaps from the input-validation review that
  are accepted as they are (MCUboot downgrade, unauthenticated D7 commands, MQTT commands
  authorised by the broker login), why, and what would reopen them.
- READMEs match gateway v2. Notes that only applied to one PC were made general. This changelog
  was added.

## Scanner firmware

### 0.8.0 (unreleased)

- Fixed: the advertised 1 m power was not range-checked. Eddystone UID/URL 0 m power below
  -87 dBm wrapped when 41 was subtracted (-100 came out as +115 dBm), and any iBeacon byte was
  passed on as is (0x7F read as "none"). Values outside -100..+20 dBm at 1 m are now dropped
  (`tx_1m_dbm` left out, the advert still counted) and counted in the new
  `Counters.tx_1m_dropped` (field 16).
- Added: debug output the gateway turns on, off at every boot. `Command.debug` (field 16,
  `DebugFlag` bits, one scanner or all; text `debug tx1m on|off`, `debug off`) and
  `Status.debug` (field 20). `DEBUG_TX_1M`: a `TxDrops` record (`Record` field 8) in the
  bucket after each second with dropped 1 m powers: per address (up to 16, the rest counted
  in `omitted`) the format, the byte as advertised, what it works out to at 1 m and how many
  adverts. It uses what RSSI and payloads left of the budget, so it never trims RSSI.
- Gateway: `<sector>/counters` now includes `ignored` (field 15, missing since 0.6.0) and
  `tx_1m_dropped`. `debug` commands on `<sector>/cmd` and `all/cmd`; `TxDrops` published on
  `<sector>/debug/tx_1m`, retained state `<sector>/debug`.
- `decode_frames.py` builds the `debug` commands and shows `TxDrops` and `Status.debug`.
- Fixed: event text is printable ASCII; anything else becomes `?` (the old version in
  `VERSION_CHANGED` comes from flash and could hold any byte).
- Fixed: the console's `budget`, `chan` and `minrssi` read the whole argument as a number
  (`budget 50x` was taken as 50, `chan 38x` as 38).
- Not built or flashed yet: no image in `scanner_fw/release/`.

### 0.7.0 (2026-11-11)

- Added: ignore list readback. The scanner sends its whole list (`IgnoreList` record, `Record`
  field 7: each rule's address, mask, saved flag and hits, plus paused) in the next bucket
  after boot, after any change, and when asked (`Command.ignore_list`, field 15, to one
  scanner or all; text `ignore list`). It goes last in the bucket, outside the byte budget,
  so it never trims RSSI.
- Gateway: publishes each scanner's list on retained `<sector>/ignore`, asks for it when it
  hasn't seen one (e.g. after a gateway restart), and raises `IGNORE_MISMATCH` (SECURITY,
  WARN) when the online scanners' lists differ, `IGNORE_MATCH` when they agree again.
- Fixed: event text (command acks) could hold only 39 characters, so longer acks such as
  `ignore list in next bucket (to all)` were cut short. The limit is now 63; the wire format
  is unchanged.
- Flashed by USB (app only) on all three XIAOs and bench-tested on each. Readback works sent
  to one chip and to all, and the list is correct when empty, with saved and boot-only rules
  and their hits, while paused, and after a clear. The 0.6.0 ignore checks pass again. The
  list sent at boot is checked in code only: it goes out before the USB console is up.
- Image: `scanner_fw/release/scanner_fw-0.7.0-dfu.zip`.

### 0.6.0 (2026-11-11)

- Added: ignore list. Up to 32 rules, each an address plus a mask (prefix `/24`, a full mask,
  or `*` bytes). Adverts that match are dropped in the scan callback, so they never reach
  RSSI, payloads, the console or the load. Each rule is saved in flash or kept until reboot.
  Console: `ignore`, `ignore <addr>[/bits|/mask] [save]`, `ignore clear boot|saved|all`,
  `ignore off|on`, `unignore`. Gateway commands `ignore` / `unignore` / `ignore_clear`,
  accepted only when sent to all scanners (the list is mast-wide)
  (Command fields 12-14, `IgnoreRule`, `IgnoreClear`). Each change is a `SETTING_CHANGED`
  security event (Setting 3 `IGNORE_LIST`). New fields: `Status.ignore_rules` /
  `ignore_saved` / `ignored` and `Counters.ignored`.
- Changed: Zephyr's shell wildcard is off (`CONFIG_SHELL_WILDCARD=n`). It swallowed arguments
  containing `*`, so `ignore C1:7D:2B:*:*:*` never reached the command.
- Gateway: parses and sends the new command words. It does not publish the new status or
  counters fields yet (that waits for its 0.5.0 update, which regenerates the self-test).
- Flashed by USB (app only) on all three XIAOs and bench-tested on each: rules and masks,
  saved rules across reboot, gateway commands via `inject` (accepted to all, rejected to one
  chip). On the bench an unconnected D7 picks up noise that can corrupt an injected frame;
  send it again.
- Image: `scanner_fw/release/scanner_fw-0.6.0-dfu.zip`.

### 0.5.0 (2026-11-10)

- Removed: the sector claim. The scanner doesn't know its sector; the gateway RX pin its D6
  is wired to decides it. Gone: `Bucket.sector`, the `sector` command and console command,
  the `SECTOR_NOT_SET` event and the `SECTOR` setting (field numbers `reserved` in the
  schema). The saved value from 0.4.x is deleted at boot. `list csv` loses its first column.
- Changed: flash mode advertises as `bletracker-<last 6 hex digits of the chip ID>` instead
  of `bletracker-s<sector>`.
- The gateway's sector-claim check has to go with it (gateway not changed yet).

### 0.4.0 (2026-11-02)

Breaking: protocol 3 replaces frame and command v2, so a gateway needs protocol 3 to read this
version or send it commands.

- Stream: one protobuf `Bucket` every 200 ms with RSSI, optional advert and scan response bytes,
  status, counters and events. Spec: `scanner_fw/PROTOCOL.md`.
- A byte budget and a throttle keep the stream inside the line, shedding payloads before RSSI.
- Commands are protobuf and acknowledged with an event. New ones: payloads, active scanning,
  intervals and budget.
- The sector is now set once at assembly (`sector 0|1|2` on the USB console) and checked by the
  gateway. A board with no saved sector now reports "not set" (255); before this version it
  showed 0, so a board that shows 0 on 0.3.x can show "not set" after updating.
- Image: `scanner_fw/release/scanner_fw-0.4.0-dfu.zip`.

### 0.3.1

- Added the `chan` console command and `tools/chan_test.py`, a bench test of primary channel
  scanning.
- No image in `scanner_fw/release/`.

### 0.3.0 (2026-10-31)

Breaking: a gateway from before this version can't read these frames, and its commands are
rejected.

- Frame v2: the header grows from 8 to 16 bytes and adds `chip_id` (the nRF FICR device ID).
- Commands v2: 13 bytes with an 8-byte `target` chip ID (all zeros = every scanner).
  v1 commands (5 bytes) are rejected as the wrong length. A sector command can't go to all
  scanners.
- Wiring: each scanner's D6 has its own gateway RX pin (that pin gives the sector), and one
  gateway TX drives every scanner's D7.
- The gateway assigns the sector (command 4); scanners need no manual sector setup.
- Image: `scanner_fw/release/scanner_fw-0.3.0-dfu.zip`.
