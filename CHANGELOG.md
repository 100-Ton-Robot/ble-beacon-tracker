# Changelog

Scanner firmware versions come from `scanner_fw/VERSION`; the gateway and the shield deck have no
version numbers yet. All versions below were made between 2026-10-29 and 2026-10-31; dates are
when the image was built, where known.

## Unreleased

### Gateway

Needs scanner firmware **0.4.0 or later** (protocol 3): v2 and v1 frames are dropped as bad.

- Changed (2026-11-02): reads protocol 3 (protobuf `Bucket` every 200 ms, CRC + COBS) with a
  small hand-written wire-format reader (`pb_wire.h`); unknown fields are skipped and unknown
  record kinds published as hex on `<sector>/raw/<n>`. UART RX buffers 4096 bytes.
- Changed (2026-11-02): MQTT layout v3 replaces the one JSON message per sector per second:
  `<sector>/rssi` (one batched message per bucket), `<sector>/adv/<ADDR>` (Theengs-style
  advert / scan response fields), `<sector>/status`, `<sector>/counters`, mast-wide `events`
  and `security`, and retained, change-only scanner state (`online`, `chip`, `claim`, `load`,
  `flash`, `listening`, `client`, `test_image`, `active`, `payloads`, `ant`). Nothing per
  address is retained. `t` is epoch milliseconds. Topics and payloads: `gateway/README.md`.
- Added (2026-11-02): `bletracker/<mast>/online` (MQTT birth / last will), retained
  `bletracker/<mast>/info` (`"format":3`), and gateway commands on `bletracker/<mast>/cmd`:
  `reboot`, `clear`. The gateway deletes and republishes its retained topics at every MQTT
  connect.
- Added (2026-11-02): SNTP clock (`ntp_server` substitution, default `pool.ntp.org`).
- Changed (2026-11-02): the gateway no longer sets the scanner's sector. It checks each
  bucket's sector claim against its RX pin (and an optional expected chip ID): mismatches are
  SECURITY errors, mark that sector's data `suspect` and turn on a "Sector N mismatch" binary
  sensor.
- Added (2026-11-02): protobuf commands with a gateway seq and ack tracking (`CMD_OK` /
  `CMD_REJECTED`, warning after 2 s without one); `payloads`, `active`, `budget`, `intervals`
  and a manual addressed `sector` command; JSON `{"cmd": ...}` accepted.
- Added (2026-11-02): settings the scanners forget at boot (payloads, active scanning,
  intervals, budget) are YAML options the gateway keeps applied.
- Added (2026-11-02): gateway-side throttle that lowers the scanners' budget when the gateway
  can't keep up; "Gateway load" and per-sector load / lost buckets / bad frames / devices /
  mismatch / chip sensors.
- Added (2026-11-02): boot self-test against the contract's command vectors and sample buckets
  generated by `gateway/tools/make_selftest.py`; result in a "Self test" text sensor.
- Changed (2026-11-02): YAML is one `sector_scanner:` hub with a `sectors:` list.

Earlier, frame v2 (scanner firmware 0.3.0):

- Changed: reads frame v2 only (16-byte header with `chip_id`).
- Added: learns each RX pin's chip ID (`chip` in the JSON, a chip text sensor per sector) and
  sets the scanner's sector to its pin's (command 4, addressed, at most every 5 s).
- Added: one shared command TX (GPIO21) to every scanner's D7. Addressed v2 commands come from
  MQTT `bletracker/<mast>/<sector>/cmd` and `bletracker/<mast>/all/cmd` (`listen`, `flash`,
  `ant`, `reboot`). Each sector gets Home Assistant buttons for flash mode and reboot.
- Added: JSON fields `scanner_sector`, `listening`, `flash`, `client`, `test_image`.
- Changed: pins are RX GPIO17/16/18 (header 34/32/31) and TX GPIO21 (35). GPIO1 and GPIO2 are
  free now.
- Changed: Home Assistant entities come over the ESPHome API and MQTT discovery is off. MQTT
  carries only beacon data and commands.
- Changed: the `api_key` secret (used for both API and OTA) replaces `ota_key`. The `mast`
  substitution names the device.
- Changed: the config is split into `packages/bletracker-gateway.yaml` (shared by every mast)
  and a per-mast file (`example-mast.yaml`). `bletracker-gateway.yaml` is no longer a device
  config on its own.

### Docs

- READMEs match gateway v2. Notes that only applied to one PC were made general. This changelog
  was added.

## Scanner firmware

### 0.5.0 (2026-11-10)

- Removed: the sector claim. The scanner doesn't know its sector; the gateway RX pin its D6
  is wired to decides it. Gone: `Bucket.sector`, the `sector` command and console command,
  the `SECTOR_NOT_SET` event and the `SECTOR` setting (field numbers `reserved` in the
  schema). The saved value from 0.4.x is deleted at boot. `list csv` loses its first column.
- Changed: flash mode advertises as `bletracker-<last 6 hex digits of the chip ID>` instead
  of `bletracker-s<sector>`.
- The gateway's sector-claim check has to go with it (gateway not changed yet).

### 0.4.0 (2026-11-02)

Breaking: protocol 3 replaces frame and command v2, so a gateway needs protocol 3 to read this
version or send it commands.

- Stream: one protobuf `Bucket` every 200 ms with RSSI, optional advert and scan response bytes,
  status, counters and events. Spec: `scanner_fw/PROTOCOL.md`.
- A byte budget and a throttle keep the stream inside the line, shedding payloads before RSSI.
- Commands are protobuf and acknowledged with an event. New ones: payloads, active scanning,
  intervals and budget.
- The sector is now set once at assembly (`sector 0|1|2` on the USB console) and checked by the
  gateway. A board with no saved sector now reports "not set" (255); before this version it
  showed 0, so a board that shows 0 on 0.3.x can show "not set" after updating.
- Image: `scanner_fw/release/scanner_fw-0.4.0-dfu.zip`.

### 0.3.1

- Added the `chan` console command and `tools/chan_test.py`, a bench test of primary channel
  scanning.
- No image in `scanner_fw/release/`.

### 0.3.0 (2026-10-31)

Breaking: a gateway from before this version can't read these frames, and its commands are
rejected.

- Frame v2: the header grows from 8 to 16 bytes and adds `chip_id` (the nRF FICR device ID).
- Commands v2: 13 bytes with an 8-byte `target` chip ID (all zeros = every scanner).
  v1 commands (5 bytes) are rejected as the wrong length. A sector command can't go to all
  scanners.
- Wiring: each scanner's D6 has its own gateway RX pin (that pin gives the sector), and one
  gateway TX drives every scanner's D7.
- The gateway assigns the sector (command 4); scanners need no manual sector setup.
- Image: `scanner_fw/release/scanner_fw-0.3.0-dfu.zip`.

### 0.2.4

- Flash mode opens only on a serial command (gateway `flash on` or the USB console). A normal
  boot no longer opens it. A test image after an update still opens it for 2 minutes.
- No image in `scanner_fw/release/`.
