# BLE Beacon Tracker (DIY)

A passive BLE beacon locator. Three Seeed XIAO nRF54L15 scanners sit behind directional antennas
facing out 120 deg apart. Comparing RSSI between sectors gives a bearing, and RSSI gives a rough
range. An ESP32-S3 Ethernet gateway (ESPHome) collects the scanners' data and publishes it to MQTT
for a tracker in Home Assistant.

Passive RSSI only: it works with any beacon, with no pairing and no Channel Sounding.

## What's here

| Folder | What it is |
| --- | --- |
| [`scanner_fw/`](scanner_fw/README.md) | Scanner firmware: nRF Connect SDK / Zephyr behind MCUboot, with signed BLE updates. Build, flash, console commands; gateway protocol in `scanner_fw/PROTOCOL.md`. |
| [`gateway/`](gateway/README.md) | ESPHome package, per-mast example config and the `sector_scanner` external component: protocol 3 buckets in, MQTT layout v3 out (batched RSSI, Theengs-style adverts, status, events, security stream, retained scanner state); the RX pin is the sector; watches each sector's chip ID, checks each scanner's firmware version and its input, drops the mast's ignore list, keeps the scanners' settings applied and passes commands to them. |
| [`shield_deck/`](shield_deck/README.md) | Copper shield deck PCB (Gerbers for any PCB fab; PCBWay order steps in [`PCBWAY.md`](shield_deck/PCBWAY.md)) and printable 1:1 drilling templates, generated by Python scripts from one `parameters.csv`; plates can be laid out in Inkscape. Steps in its README. |
| [`rf_model/`](rf_model/README.md) | openEMS (FDTD) model of one sector: deck, core and whips from `parameters.csv`; gives the antenna pattern, match and isolation between sectors. Runs in Docker. |
| [`experiments/`](experiments/kicad_deck/README.md) | Side experiments (the deck redone in KiCad). |

Changes are listed in [`CHANGELOG.md`](CHANGELOG.md). How to report a vulnerability, and the
known security gaps that were reviewed and accepted (with the reasons), are in
[`SECURITY.md`](SECURITY.md). Prebuilt scanner update images are in
`scanner_fw/release/`. They only install on scanners whose
MCUboot was built with the same signing key, so build your own from source with your own key
(see `scanner_fw/README.md`).

## Status

Work in progress:
- Scanner firmware 0.4.0 (protocol 3) runs on three boards, checked over the USB console. Its
  D6 output and BLE update path haven't been tested on this version yet.
- The gateway (protocol 3, needs scanner firmware 0.4.0 or later) passes its boot self-test on
  a board, but hasn't received scanner data on real wiring yet.
- The Home Assistant tracker isn't written yet.

## Bugs and contributions

Bug reports and pull requests are welcome: use [Issues](../../issues). For firmware problems,
include the version, the console's `status` output and what you expected to happen.
